## Technical Manifesto

- **Direct Kernel-Level Interfacing:** Bypasses display server abstraction barriers by capturing hardware events directly via `evdev` (`/dev/input/event*`) and injecting emulated events via the kernel's virtual device interface (`/dev/uinput`).
- **Hardware-Level Camouflage:** Simulates physical USB bus architectures (`BUS_USB`) with authentic Vendor/Product ID spoofing, eliminating generic virtual emulator detection signatures.
- **Zero-Copy Memory-Mapped Perception:** Implements pure-Rust Zero-Mean Normalized Cross-Correlation (ZNCC) with alpha channel masking, operating directly over shared memory framebuffers (`/dev/shm`) at sub-millisecond latencies.
- **Biomechanical Kinematics:** Replaces linear pointer translations with cubic Bézier trajectory synthesis, ease-in/ease-out physiological velocity curves, and stochastic Gaussian micro-jitters.
- **Deterministic Offline Architecture:** 100% self-contained, zero network telemetry, zero daemon services, and ACID-compliant atomic persistence.

## 1. Linux Kernel Input Subsystem (`evdev` & `/dev/uinput`)

### Data Pipeline & Event Lifecycle
```text
1. **Physical Peripheral Input:** Hardware signals generated by physical keyboard or mouse devices.
2. **Kernel Event Dispatch:** Linux input drivers emit serialized `struct input_event` packets to `/dev/input/event*`.
3. **Capture Poller Thread:** oGiuMacro thread reads directly from `/dev/input/event*` with microsecond monotonic timestamps.
4. **Virtual HID Controller:** Synthesizes actions, applies layout conversion (ABNT2 / US), and binds USB spoofing descriptors.
5. **Virtual Device Injection:** Writes synthetic event buffers via `ioctl` directly into `/dev/uinput`.
6. **Display Server Routing:** Linux input subsystem dispatches the virtual peripheral events to the active compositor (Wayland or X11).
7. **Target Application:** Target process consumes authentic input events without user-space software hooks.
```

### Event Interception Mechanism (`evdev`)
Input capture operates at the driver layer rather than using X11 event hooks or Wayland window focus:
- Reads directly from character device nodes (`/dev/input/event*`).
- Processes sequential streams of `struct input_event`:
  ```text
  struct input_event {
      struct timeval time;   /* Monotonic microsecond timestamp */
      __u16 type;            /* EV_KEY, EV_REL, EV_ABS, EV_SYN */
      __u16 code;            /* Physical scan code or axis identifier */
      __s32 value;           /* Key state (0: release, 1: press, 2: repeat) or relative motion delta */
  };
  ```
- **Monotonic Microsecond Accounting:** Event timing deltas are computed against the kernel's monotonic hardware clock (`CLOCK_MONOTONIC`), eliminating drift across long execution loops.

### Virtual Device Initialization via `ioctl` Sequence
oGiuMacro communicates with the `/dev/uinput` character device through sequential control codes:
```text
1. `UI_SET_EVBIT`: Declares operational event categories (`EV_KEY`, `EV_SYN`, `EV_REL`, `EV_ABS`).
2. `UI_SET_KEYBIT`: Registers support for all 256 physical scancodes, mouse buttons (`BTN_LEFT`, `BTN_RIGHT`, `BTN_MIDDLE`, `BTN_SIDE`, `BTN_EXTRA`), and system control keys.
3. `UI_SET_RELBIT`: Binds relative axes for pointer translation (`REL_X`, `REL_Y`) and 4-way scroll wheels (`REL_WHEEL`, `REL_HWHEEL`).
4. `UI_DEV_SETUP`: Populates the `uinput_setup` structure (Vendor ID, Product ID, Bus Type, and Name).
5. `UI_DEV_CREATE`: Issues the kernel directive to instantiate the device node.
```

### Hardware USB Spoofing (Anti-Detection)
Virtual input software commonly exposes identifiable signatures (`BUS_VIRTUAL`, Vendor `0x0000`, Product `0x0000`), allowing target applications or anti-cheat heuristics to reject input.

oGiuMacro overrides the device identification descriptor during `UI_DEV_SETUP`:
```text
struct input_id {
    __u16 bustype;  /* Overridden to BUS_USB (0x03) */
    __u16 vendor;   /* Arbitrary hardware Vendor ID (e.g. 0x046D for Logitech) */
    __u16 product;  /* Arbitrary hardware Product ID (e.g. 0xC077 for Optical Mouse) */
    __u16 version;  /* Device driver firmware revision */
};
```
The Linux kernel registers the device as an authentic physical peripheral connected to a hardware USB root hub.

### Scancode Physical Mapping (ABNT2 vs. US International)
Because `/dev/uinput` operates beneath the display server's keymap translation layer (XKB), characters cannot be emitted as UTF-8 codepoints; they must be generated as physical scancodes.

oGiuMacro implements low-level scancode conversion tables:
- **Brazilian ABNT2 Physical Scancodes:**
  - `KEY_RO` (`scancode 89`): Native physical key for `/` and `?`, avoiding dead-key artifacts.
  - `KEY_SEMICOLON` (`scancode 39`): Native generation of `ç` and `Ç`.
  - Dedication of `KEY_SLASH` (`scancode 53`) for `:` and `;`.
- **Dead-Key Accent Engine:** Automatically decomposes composite accented glyphs into chronological scancode pairs:
  $$\text{Accent Dead Key Press} \longrightarrow \text{Sync} \longrightarrow \text{Release} \longrightarrow \text{Base Character Press} \longrightarrow \text{Sync} \longrightarrow \text{Release}$$

## 2. Display Server IPC & Screen Capture Internals

Screen perception operates across both X11 and Wayland protocols through specialized memory-mapped capture pipelines:

| Protocol / Engine | Mechanism | Frame Latency (1080p) | Disk I/O | Memory Footprint |
| :--- | :--- | :--- | :--- | :--- |
| **X11 Fast Memory (`XShm`)** | Zero-copy shared memory extension (`XShmGetImage`) | **0.05 – 1.5 ms** | None (`/dev/shm`) | Single shared frame buffer |
| **Wayland Desktop Portal (`ScreenCast`)** | D-Bus Session Desktop Portal with SHM buffer | **12 – 22 ms** | None (`/dev/shm`) | Zero-copy stream buffer |
| **X11 CLI Fallback (`scrot`)** | Subprocess invocation with uncompressed PPM | **30 – 50 ms** | RAM-backed (`/dev/shm`) | Ephemeral process buffer |
| **Wayland Coordinate Picker (`slurp`)** | Native interactive crosshair overlay for `(X, Y)` picking | Interactive | None | Ephemeral helper process |

### Zero-Copy X11 Shared Memory (`XShm`)
Under X11, standard `XGetImage` transfers pixel data over the local UNIX domain socket, incurring severe serialization overhead. oGiuMacro utilizes the MIT-SHM extension:
1. Allocates a System V shared memory segment (`shmget`).
2. Attaches the memory block to the process address space (`shmat`).
3. Notifies the X server to attach to the same segment (`XShmAttach`).
4. Queries frames via `XShmGetImage` directly into shared RAM at up to 300+ FPS, throttled to 60 FPS for template matching.

### Wayland Eavesdropping (KDE Plasma 6)
On modern KDE Wayland sessions, Xwayland restricts applications from capturing the global screen. oGiuMacro programmatically inspects and configures the KDE compositor:
- Reads status via `kreadconfig6 --file kwinrc --group Xwayland --key XwaylandEavesdrops`.
- Applies `XwaylandEavesdrops=All` via `kwriteconfig6` to grant seamless cross-window capture access without root privileges.

## 3. Computer Vision & Template Matching Engine

Template matching is implemented in pure Rust with zero external C/C++ computer vision dependencies (no OpenCV runtime requirement).

### Mathematical Model: ZNCC (Zero-Mean Normalized Cross-Correlation)
To maintain detection invariant to linear shifts in desktop illumination, contrast adjustments, and dark/light mode transitions, matching evaluates the zero-mean normalized cross-correlation:

$$\rho(x, y) = \frac{\sum_{i=0}^{W-1} \sum_{j=0}^{H-1} M(i,j) \cdot [T(i,j) - \mu_T] \cdot [I(x+i, y+j) - \mu_{I,(x,y)}]}{\sqrt{\left( \sum_{i=0}^{W-1} \sum_{j=0}^{H-1} M(i,j) \cdot [T(i,j) - \mu_T]^2 \right) \cdot \left( \sum_{i=0}^{W-1} \sum_{j=0}^{H-1} M(i,j) \cdot [I(x+i, y+j) - \mu_{I,(x,y)}]^2 \right)}}$$

Where:
- $T(i, j)$ is the template pixel intensity at local coordinate $(i, j)$.
- $I(x+i, y+j)$ is the screen pixel intensity offset by candidate origin $(x, y)$.
- $\mu_T = \frac{1}{N} \sum M(i,j) T(i,j)$ is the mean intensity of the template.
- $\mu_{I,(x,y)} = \frac{1}{N} \sum M(i,j) I(x+i, y+j)$ is the mean intensity of the local screen patch.
- $M(i, j) \in \{0, 1\}$ is the transparency mask.
- $\rho(x, y) \in [-1.0, 1.0]$: Correlation coefficient where $1.0$ represents an exact structural match.

### Alpha Channel Dynamic Sprite Masking
For UI elements or game sprites moving across variable, animated backgrounds:
- Pixels with $\text{Alpha} < 128$ are assigned $M(i, j) = 0$.
- Opaque pixels ($\text{Alpha} \ge 128$) are assigned $M(i, j) = 1$.
- Zero-masked pixels contribute zero weight to $\mu_T$, $\mu_I$, covariance, and variance terms, ensuring background variance does not degrade the correlation coefficient.

## 4. Biomechanical Kinematics & Trajectory Engine

To prevent detection by heuristics monitoring pointer kinematics (constant velocity vectors, zero acceleration derivatives, strictly linear paths), oGiuMacro computes pointer paths using neuromuscular motor models.

### Trajectory Generation Stages
1. **Vector Sampling:** Derives initial position ($P_0$), dynamically generated orthogonal control points ($P_1, P_2$), and target destination ($P_3$).
2. **Cubic Bézier Interpolation:** Computes the smooth curved trajectory $B(t)$ over normalized transit time $t \in [0, 1]$.
3. **Sigmoidal Velocity Modulation:** Applies ease-in/ease-out physiological acceleration to mimic human muscular inertia.
4. **Gaussian Micro-Jitter:** Introduces low-amplitude spatial perturbations and temporal jitter.
5. **Driver Dispatch:** Emits sequential relative motion deltas (`EV_REL`, `EV_SYN`) directly to `/dev/uinput`.

### 1. Cubic Bézier Curve Interpolation
Trajectories are synthesized as parametric curves defined by four points:

$$B(t) = (1-t)^3 P_0 + 3(1-t)^2 t P_1 + 3(1-t) t^2 P_2 + t^3 P_3, \quad t \in [0, 1]$$

- $P_0$: Motion origin vector.
- $P_3$: Target destination vector.
- $P_1, P_2$: Dynamically computed control points placed orthogonally to the chord $\vec{P_0 P_3}$. Orthogonal displacement scales with distance and curvature bias, replicating natural arm and wrist articulation.

### 2. Neuromuscular Velocity Curve (Sigmoidal Acceleration)
Linear interpolation ($t = \frac{\Delta t}{T}$) is replaced by sigmoidal velocity mapping:

$$S(t) = \frac{1}{1 + e^{-k(t - 0.5)}}$$

Velocity starts near zero (inertia overcoming), peaks during mid-transit, and decelerates asymptotically upon target arrival to model human hand target acquisition.

### 3. Stochastic Gaussian Perturbation & Temporal Jitter
- **Spatial Tremor:** Adds low-amplitude zero-mean Gaussian displacement:
  $$P_{\text{final}}(t) = B(t) + \mathcal{N}(0, \sigma^2), \quad \sigma \in [0.5, 1.8] \text{ pixels}$$
- **Temporal Jitter:** Delay intervals between actions deviate by random variables sampled from normal distributions ($\pm 15\%\text{--}30\%$), breaking rigid periodic timing signatures.

## 5. Security, Privilege Model & POSIX Integration

### Rootless Operation via Udev Dynamic Access Control
Access to `/dev/uinput` and `/dev/input/event*` typically requires superuser permissions. oGiuMacro integrates with systemd-logind via a dedicated udev rule:

```udev
# /etc/udev/rules.d/99-ogiumacro.rules
KERNEL=="uinput", SUBSYSTEM=="misc", TAG+="uaccess", OPTIONS+="static_node=uinput"
SUBSYSTEM=="input", ENV{ID_INPUT}=="?*", TAG+="uaccess"
```

The `TAG+="uaccess"` flag directs `systemd-uaccess` to dynamically apply POSIX Access Control Lists (ACLs) to the local active console session user, enabling unprivileged execution without root daemons or `setuid` binaries.

### Polkit (`pkexec`) Fallback & Environment Passthrough
When executed under `pkexec`:
- Forwards critical session descriptors: `DISPLAY`, `XAUTHORITY`, `WAYLAND_DISPLAY`, and `XDG_RUNTIME_DIR`.
- **POSIX Ownership Normalization (`fix_ownership`):** Detects `PKEXEC_UID` / `SUDO_USER` and executes `libc::chown()` on all created configuration directories and files, preventing permission locks when subsequently accessed by unprivileged users.

### Thread-Isolated Emergency Interrupt
- The global hotkey listener runs on an independent POSIX thread reading raw scancodes directly from `/dev/input/event*`.
- **Triple-ESC Interruption:** Detecting the `KEY_ESC` scancode **3 times within 1.2 seconds (1200 ms)** immediately sets an atomic boolean flag (`Ordering::SeqCst`), tearing down running macros, clearing all held virtual keys/buttons, and returning the system to a clean state.

## 6. Storage Architecture & Namespace Isolation

User configurations, runtime session caches, and standalone exported macros are stored within `~/.config/oGiuMacro/`:

```text
~/.config/oGiuMacro/
├── macros.json           # Active session state: Main Tab workflow sequence
├── recordings.json       # Active session state: Rec/Play event stream
├── hardware.json         # Configured hardware spoofing profiles (VID/PID)
├── quick_tags.json       # Validated shortcut chip definitions
├── skip_diagnosis.json   # Diagnostic modal display preference
├── workflows/            # Isolated namespace: Exported Workflow macro files (*.json)
└── recordings/           # Isolated namespace: Exported Rec/Play macro files (*.json)
```

### Namespace Separation & Independent Naming
- **Directory Isolation:** Procedural workflows are strictly isolated in `workflows/`; raw kernel recordings reside in `recordings/`.
- **Zero Collision:** Identical filenames (e.g., `workflows/Farm.json` and `recordings/Farm.json`) coexist simultaneously without collision or overwrite warnings.
- **Schema Validation & Cross-Import Prevention:** `detect_macro_file_type()` inspects root JSON keys before loading (`actions` vs. `events`). Cross-importing incompatible formats is strictly rejected at the engine level.

### ACID-Compliant Atomic File Transactions
To prevent file corruption caused by power interruptions or abrupt termination:
1. Writes are buffered to an ephemeral temporary file: `.tmp_<nanoseconds>`.
2. Flushes buffers to disk.
3. Invokes atomic POSIX `rename()` over the target filename.
4. Synchronizes ownership metadata via `libc::chown()`.
